# Formats

Length is a ceiling, not a target. Cut first. Front-load the payoff in every format.

## Landing / hero

- Brand (or product name) first on branded surfaces.
- One problem, one promise, one primary CTA. Optional secondary CTA that is a different verb, not a synonym.
- Support line adds a mechanism or constraint, not a second slogan.
- Features: name the job, the mechanism, and (if real) the proof. No icon-row of adjectives.
- Typical hero: headline ≤ 12 words, support ≤ 2 sentences, CTA 2–5 words, sentence case.

## Release notes / changelog blurb

- Accuracy is [agent-docs](../../agent-docs/SKILL.md). This file is voice only.
- Lead with user-visible behavior, not ticket ids.
- Group by what changed for the reader (fixed, added, removed). Skip "We're excited to ship".
- One sentence of context only when the change is otherwise opaque.
- Do not invent metrics for "faster" or "more reliable".

## Product email / announcement

- Subject line is the payoff, not a teaser. Offer 2–3 subject variants.
- First line must stand if the rest is clipped.
- One ask. Links that are not the ask go after.
- No fake urgency. Real expiry dates are fine.

## Docs lead (README, landing narrative)

- What it is, who it is for, what to run first.
- No manifesto. Link deeper pages instead of stacking slogans.
- Keep glossary terms aligned with UI.

## Social / short post

- One idea. Specific number or mechanism if you have one; otherwise a concrete job.
- No engagement-bait questions. No "thread incoming" theater.
- Variants: 2–3 hooks labeled (direct / proof / status-quo).

## UI microcopy, empty states, errors

- Buttons and menus: verb-first, sentence case, 1–4 words.
- Empty state: what is missing, why it matters, the next action.
- Error: what happened, why if useful, what to do next. Never blame the user. Never show only an internal code.
- Confirmations: name the consequence ("Delete workspace? This cannot be undone."), not "Are you sure?"

## Sales one-pager / feature description

- Audience from [audiences.md](./audiences.md). Economic buyers get outcome and constraint; practitioners get mechanism.
- Proof adjacent to each claim, or a visible placeholder.
- CTA is a specific next step (book a walkthrough of X, run the quickstart), not "Get started" unless that is the label on the button.
