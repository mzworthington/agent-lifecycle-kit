Eval-Driven Development

TDD for agents that call tools. Treat prompts and MCP schemas like code contracts— something you can assert, gate, and improve—not a vibe you hope holds in prod.

Fresh context each case

Mocked tools

Stub the payloads so you measure routing and extraction—not someone else’s API latency.

Schema + judgment

Strict JSON schema match, plus an optional LLM-as-a-judge when the answer isn’t structured.

CI, then prod feedback

Gate PRs on a threshold. Turn production misses into new cases. Sample live traffic with a shadow judge.

kit eval
# Red → green → refactor on a suite
$ kit eval run --suite evals/edd/architecture_routing.yaml --model scripted

# Block the merge if routing accuracy drops below 95%
$ kit eval ci --threshold-routing 95 --out out/reports

# Markdown failure report for the PR
$ kit eval report --format md --out out/reports
